Testing og_consumable ​

Use this whenever you change item config, exporter logic, metadata behavior, effects, or inventory returns.

Offline Tests ​

Run the full local test runner:

powershell
.\tools\test-consumables.ps1

Run strict mode:

powershell
.\tools\test-consumables.ps1 -Strict

Run one business:

powershell
.\tools\test-consumables.ps1 -Business blackstag

What it checks:

  • Consumable config can be parsed.
  • Generated ox files exist and match the configured export.
  • Generated items use consume = 0.
  • Generated files do not contain smart punctuation.
  • Live ox item files are checked when the configured ox path exists.

Current expected baseline:

text
Businesses: blackstag, peds, uwucafe
Consumables: 49

Server Test Commands ​

Commands are controlled by:

lua
Config.TestCommands = {
    enabled = true, -- set false for live unless actively testing
    ace = 'og_consumable.admin',
    allowConsole = true
}

Default live config keeps test commands disabled. Turn them on only while testing, then restart og_consumable.

Give access in server.cfg:

text
add_ace group.admin og_consumable.admin allow

Print all dev commands:

text
/ogc_help

Inspect config and ox hookup:

text
/ogc_check gp_stagcola
/ogc_dump gp_stagcola
/ogc_returns gp_stagcola

List configured items:

text
/ogc_businesses
/ogc_categories blackstag
/ogc_list
/ogc_list blackstag
/ogc_list blackstag house_drinks drink

Inventory tools:

text
/ogc_give gp_stagcola 1
/ogc_giveall blackstag 1
/ogc_take gp_stagcola 1
/ogc_count gp_stagcola
/ogc_slots gp_stagcola

Metadata inventory test:

text
/ogc_give gp_stagcola 1 {"batch":"test-001","maker":"Black Stag"}
/ogc_count gp_stagcola {"batch":"test-001","maker":"Black Stag"}

Use-path tests:

text
/ogc_canuse gp_stagcola
/ogc_preview gp_stagcola
/ogc_use gp_stagcola
/ogc_cancel

/ogc_preview only tests progress/animation/prop. /ogc_use runs the full OG path, including progress, removal, status, add/dirty returns, effects, and alcohol.

Effects and alcohol:

text
/ogc_effects gp_stagcola
/ogc_alcohol gp_stagreserve

Status and cooldown tools:

text
/ogc_status
/ogc_setstatus hunger 50
/ogc_setstatus thirst 50
/ogc_setstatus stress 20
/ogc_cooldown clear
/ogc_cooldown clear gp_stagcola

Debug/runtime tools:

text
/ogc_active
/ogc_debug on
/ogc_debug off

Whitelist Admin Commands ​

Whitelist commands are controlled separately from test commands and are enabled by default in live config:

lua
Config.WhitelistCommands = {
    enabled = true,
    ace = 'og_consumable.admin',
    allowConsole = true
}

Runtime whitelist commands:

text
/ogc_whitelist add pd_dog_treat playerId
/ogc_whitelist add pd_dog_treat citizenid
/ogc_whitelist remove pd_dog_treat playerId
/ogc_whitelist remove pd_dog_treat citizenid
/ogc_whitelist list pd_dog_treat
/ogc_whitelist clear pd_dog_treat

From server console, include the target id on player-specific commands:

text
ogc_give 1 gp_stagcola 1 {"batch":"test-001","maker":"Black Stag"}
ogc_use 1 gp_stagcola
ogc_status 1
ogc_setstatus 1 thirst 50

Dog Ped Treat ​

pd_dog_treat is managed by og_consumable in the peds business. It has no animation, removes one treat, and gives repeated stamina restore for 10 minutes.

Allowed by default:

  • dog ped models in the item config
  • runtime citizen ID whitelist entries added with /ogc_whitelist

Runtime whitelist JSON is stored by item name:

json
{
  "pd_dog_treat": {
    "item": "pd_dog_treat",
    "label": "Police Dog Treat",
    "citizenids": [
      "ABC12345"
    ]
  }
}

Test flow:

  1. As a normal ped, run /ogc_give pd_dog_treat 1.
  2. Try to use it from ox_inventory and confirm it blocks with "Only dog peds can use this treat."
  3. Switch to a dog ped and use it again.
  4. Confirm the item removes once and stamina keeps restoring.
  5. Test whitelist override with /ogc_whitelist add pd_dog_treat playerId or /ogc_whitelist add pd_dog_treat citizenid.

Manual In-Server Test Pass ​

For each business, test at least one drink, one food, one item with a return item, and one item with custom effects.

Use this flow:

  1. Run /ogc_check item_name.
  2. Run /ogc_give item_name 1.
  3. Use the item from ox_inventory.
  4. Confirm progress starts and can cancel.
  5. Confirm success removes the used item.
  6. Confirm hunger/thirst/stress changes.
  7. Confirm dirty/add items are returned.
  8. Confirm effects start and clean up after their duration.
  9. Test with full inventory if the item returns something.
  10. Test restart/resource stop while effects are active.

For metadata-aware items, use /ogc_give with JSON metadata, then confirm returned items keep or transform the metadata exactly as configured.

Alcohol / NRG AlcoEffect ​

For alcohol managed by og_consumable, OG should own:

  • progress
  • item removal
  • thirst/stress
  • dirty glass/return items
  • normal item notifications

NRG should only receive the BAC/drunk effect through the item alcohol config.

Before testing an OG-managed alcohol item, make sure the same item is not also configured in nrg_alcoeffect with thirst/stress/removal behavior. The NRG breathalyzer can stay configured normally.

Test flow:

  1. Run /ogc_check gp_stagreserve and confirm it reports alcohol config.
  2. Give the item with /ogc_give gp_stagreserve 1.
  3. Use it from ox_inventory.
  4. Confirm OG progress/removal/dirty glass/status work once.
  5. Confirm NRG BAC/drunk behavior applies once.
  6. Watch for double animation; if NRG also plays its own drink animation, test the item with alcohol.prop and alcohol.propOffset removed.
